# 国語AI誤答生成スパイク

「さくらのAI Engine 3,000リクエスト使い切りチャレンジ」向けの検証スクリプト。漢字よみクイズの
4択のうち、正解は`sample-kanji-master.json`（学年別漢字配当表由来のマスタデータ、という想定の
サンプル）にDBで持たせた確定データとし、誤答3つだけをAIに考えさせて、正解データと機械的に
突き合わせて検証する——というのがこのスパイクの本題。

## アプリ本体には未接続

`docs/architecture.md`には「算数側（ひき算・タイムアタック・ランキング）が揃うまで他教科へ広げ
ない」という着手順序が明記されている。現状はまだ揃っていないため、このスクリプトはアプリの
DBスキーマ・回答UI・出題フローには一切触れない、standaloneのNodeスクリプトとして置いている。
実際に国語をアプリへ組み込むと判断が変わったら、まず`docs/architecture.md`と`docs/data-model.md`
を更新してから着手すること。

## サンプルマスタデータについて

`sample-kanji-master.json`は小学1年生の漢字のうちごく一部（15字）を手動でピックアップしたもの
で、**文部科学省の学年別漢字配当表（80字）そのものではない**。実際にコンテンツとして使うなら、
配当表の原本を正として全80字ぶんのデータを作り直し、人間がレビューする必要がある。

## 検証ロジック

AIが返した誤答候補は、以下を満たすものだけを採用する（`validateDistractors`）。

- ひらがなのみ（漢字・カタカナ・記号が混ざっていたら却下）
- そのマスタエントリの`correctReadings`（正しい読み方全部）のいずれとも不一致
  - ＝ AIの誤答候補が偶然「その漢字の別の正しい読み方」と一致し、4択の中に正解が2つ紛れ込む
    事故を防ぐのがここの目的
- 重複していない

検証後に3件揃わなかった漢字はスキップし、理由を標準出力に出す（再プロンプトのリトライは
このスパイクではやらない）。

## 実行方法

```bash
npm run kokugo:generate-distractors
```

`.env`に以下を設定しておく（`.env.local.example`参照）。

```
SAKURA_AI_API_KEY=
SAKURA_AI_BASE_URL=
SAKURA_AI_MODEL=
```

`SAKURA_AI_BASE_URL`はさくらのAI Engineのコントロールパネルに表示されるOpenAI互換エンドポイント
のベースURLをそのまま設定する（このリポジトリ側では決め打ちにしていない）。

## 出力

`scripts/kokugo-ai/output/quiz-candidates.json`に生成結果を書き出す（`.gitignore`済み・未レビュー
のAI生成物のためコミットしない）。各要素は`needsHumanReview: true`を必ず持つ——人間のレビューを
経るまでは実データとして扱わない、という運用を機械的にも示すため。
