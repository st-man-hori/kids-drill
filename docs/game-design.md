# game-design

## コンセプト

紙のドリルにはない「デジタルである強み」を活かす。単一の報酬だけだとすぐ飽きるため、時間スケールの異なる報酬を重ねて設計する。

## 報酬ループ（多層構造）

| スケール | 仕組み |
|---|---|
| 1問ごと | 正解モーション・エフェクト |
| 1セッション内 | 連続正解コンボ演出 |
| 中期 | ポイントを貯めて着せ替えアイテムと交換 |
| 長期 | 着せ替えアイテムを集めてコーディネート |
| 継続的比較 | 自己ベスト／ランキング（タイムアタックモード） |

### ポイントの付与レート（練習モード）

- 正解1問につき **10ポイント**
- 10問すべて正解でさらに **50ポイント** のボーナス（1問も落とさないことに価値を持たせる）

着せ替えアイテムの価格が未定のため暫定値。アイテムのラインナップを決める時に、
「何セッションでどのくらい貯まるか」から改めてバランス調整する。

## 出題ロジック・難易度カーブ

難易度は「桁数」より「繰り上がり・繰り下がりの有無」を主軸に設計する（小学校算数で実際の壁になるのはここのため）。小1のたし算は例えばこう並べる（ひき算も同じ考え方で繰り下がりなし→ありの順）。

| Lv | 内容 | 例 |
|---|---|---|
| 1 | 1桁+1桁、繰り上がりなし（和≤10） | 3+4 |
| 2 | 1桁+1桁、繰り上がりあり（和11〜18） | 8+5 |
| 3 | 10+1桁 | 10+7 |
| 4 | 2桁(11〜19)+1桁、繰り上がりなし | 13+4 |
| 5 | 2桁(11〜19)+1桁、繰り上がりあり（挑戦枠） | 18+5 |

「2桁+2桁」以降は小2の範囲としてLv6以降に追加する。各レベルは`{min_a, max_a, min_b, max_b, carry}`のような設定データとして持たせ、コード変更なしでレベル追加できるようにする。レベルアップ判定は「直近10問中8問正解で次のレベルへ」を基準とする。たし算・ひき算は別々にレベル管理する。

### 降級

**10問中4問以下のセッションが2回続いたら、レベルを1つ下げる。**

昇級だけあって降級が無いと、まぐれで8問正解して上がった子が「毎回2〜3問しか解けないレベル」に固定され、自力で戻る手段が無くなる。ポイントも貯まらず着せ替えも解放されず、上の報酬ループが全部止まるため、離脱要因として最も太い。

- **4問以下**: 当てずっぽうでも当たる範囲を下回っている＝明確に手が出ていない水準
- **2回連続**: 眠い・気が散ったといった1回のコケで下げないため
- **判定対象は「今のレベルで解いたセッション」に限る**。降級直後は対象が0件になるので、1回の不調で下まで転げ落ちることはない
- Lv1からはそれ以上下げない

**降級は演出しない。** 「レベルが下がりました」という通知は子どもにとって罰であり、昇級の祝祭と対称に扱ってはいけない。黙って易しい問題が出るだけにする（昇級だけ盛大に祝う非対称でよい）。

**プレイ画面にレベル番号を表示しない。** 通知しなくても「レベル3」→「レベル2」という数字の変化は数字が読める子には見えてしまい、結局「下がったこと」を突きつける形になる。昇級時のメッセージも数字を出さず「つぎは もうすこし むずかしいよ」と伝える。子どもが自分の状態を知る手がかりは、レベル番号ではなく問題そのものの手応え・ポイント・着せ替えの解放でよい。

### レベルの手動選択について

練習モードのレベルは選択制にせず、上記の自動昇降のみとする。

- 現在ポイントはレベル非依存（正解10pt + 全問正解50pt）なので、自由に選べると**Lv1を回すのが最適**になり、着せ替え目当てで一番簡単な問題を繰り返す行動を誘発する。ランキングをタイムアタック限定にしたのと同じ理由
- 「今日どのレベルをやる？」という選択は6歳児には負荷。数字PINパッドUIを選んだのと同じ判断

将来レベル数とスキル種別が増えたら（小2以降）、**到達済みレベルのみ選べる「ふくしゅう」の別導線・ポイントは半減または無し**という形で入れる余地がある。その場合はポイントのレベル別重み付けとセットで検討すること。

### 実装上の扱い（練習モード）

- **1セッション = 10問**を単位として`practice_sessions`に1レコード記録し、そのタイミングでレベルアップを判定する。「もっとやる」で延長した分は次の10問＝別レコードとして記録する（結果画面を見たまま離脱しても、終わった10問の記録は残る）
- レベルアップした場合、次の10問から新しいレベルの問題になる（プレイ中に難易度が変わらないようにする）。降級も同様に次の10問から反映する
- 降級判定は今回のセッションを含む直近の記録を見るため、`practice_sessions`への記録→レベル変更の順で処理する。記録は必ず変更前のレベルIDで残る
- 最高レベルに到達済みの場合はレベルアップせず、そのレベルを繰り返す
- 出題レベルと獲得ポイントは**サーバー側で`child_progress`から導出**する。Server Actionは画面を経由せず直接POSTできるため、レベルIDや点数をクライアントの申告のまま信用しない

## モード設計

- **練習モード**（問題数ベース）: 日々の学習用。デフォルト10問、終了後に「もっとやる？」で+10問ずつ延長可能。ポイント・着せ替えアイテム解放に反映。ランキングには影響しない。プレッシャーなく自由に練習できることを重視する。フィードバックはフル（正解モーション・キャラ反応・獲得ポイント表示など）
- **タイムアタックモード**（60秒間固定）: ランキング専用モード。問題数の上限は設けず、時間切れまで出題し続ける。不正解には数秒のペナルティ（例: 3秒ロス）を課し、速さと正確さのバランスを取る。スコア＝時間内の正解数。フィードバックは最小限（○✕を一瞬フラッシュ、ペナルティ時のみ「-3秒」を一瞬添える程度）で、テンポを止めない

## 着せ替えアバター

進化ではなく「人間のアバター1体＋着せ替えアイテム」方式。集める対象がキャラ丸ごとではなく着せ替えアイテムになる。

- ベースアバターは1体（見た目は最初にシンプルに選択）
- アイテムスロット: 髪型・トップス・ボトムス・ネックレス（データ駆動で今後追加可能。アクセサリーは抽象的すぎるため、まずネックレス1種類にミニマムに絞る。将来的に帽子・メガネなどを追加する場合は新しいslot_typeを足すだけでよい）
- 各アイテムに解放条件を個別設定できる（例: 累計正解100問／たし算Lv3到達／タイムアタック20点達成など）
- 新アイテム追加は図鑑にレコードを1件足すだけ（コード変更不要）
- 全身別キャラを複数描くより、ベース1体＋アイテム差分の方がアセット制作コストが低い。
- イラストはAI生成を活用してアセット制作コストを抑える

## ランキング設計

- スコアはタイムアタックモードの「時間内正解数」を使用する（練習モードのプレイ量そのものは反映しない。学習目的からズレた行動＝雑な連打を誘発しないため）
- **学年別セグメント必須**（1年生が6年生と同じ土俵で比較されないように）
- **週間リセット**（後から始めた子も上位を狙えるよう、全期間の一発勝負にしない）
- 見せ方はやさしく。自己ベストとの比較を主役にし、ランキングは「上位◯%」のようなバッジ表示を基本にする。詳細な数値順位は任意で見られる程度に留める

## 自己ベスト

- タイムアタックモードのスコア記録。自分のみに表示（安全）

## 表示用ニックネーム（ランキング用）

- ログイン用IDとは別に、プロフィール作成時にシステムが自動生成する
- 自由入力にしない（不適切な文字列のモデレーションが不要になる）
- ログインIDをそのまま公開しない（IDが割れるとPIN総当たりの的を絞られてしまうため）

**生成方式**: 形容詞＋名詞（動物など）＋数字3桁のランダム組み合わせ（例:「げんきなトラ402」）

- 組み合わせ数を十分広く取る（例: 形容詞40種×名詞40種×数字900通り ≒ 144万通り）ことで実用上の衝突はほぼ発生しない
- `nickname`カラムに`UNIQUE`制約を設定
- 生成時は「先にINSERTを試みて、重複エラーが返ったら再生成してリトライ」する方式にする（SELECTで存在確認してからINSERTすると競合状態のリスクがあるため）
