# architecture

## 概要

サービス名は「さんすうチャレンジ」（リポジトリ名・開発コードネームは`kids-drill`のまま）。算数ドリル学習サービス。小学1年生のたし算・ひき算から始め、小学1〜6年生の算数（四則演算・分数・小数・割合・図形・代数の初歩など）まで拡張予定。

算数に絞っているのは意図的な判断。算数はパラメータからの動的な問題生成でほぼ全範囲をカバーでき、個人開発の工数でも小6まで現実的に到達できる。一方、国語などの他教科は漢字・語彙・読解のように実データのキュレーションが必要でコスト構造が大きく異なるため、現時点では計画していない。DBの`subjects`テーブルはレコード追加のみで教科拡張できる設計になっており、将来本当に必要になれば対応できる（＝今からその前提でアーキテクチャを複雑にする必要はない）。

## ターゲット

- 対象ユーザー: 小学生全般※サービス開始時のコンテンツは小学1年生の算数（たし算・ひき算）から
- 対応デバイス優先度: タブレット・スマホ ＞ PC（タッチファースト）

## 認証設計

親アカウントという別レイヤーは持たず、アカウントは子どもごとの1つのみ。登録作業は親子一緒に行う（親が発行をサポートする）想定。

- 登録時にID（一意）とひみつのばんごう（6桁の数字PIN）を発行し、紙に書いて子どもに渡す運用
- PINは数字のみ・6桁。4桁＋レート制限でも実用上は十分（ATMのPINと同様の考え方）だが、親子で発行する認証情報として余裕を持たせて6桁に。英字混在にはしない（通常キーボード入力が必要になり、数字PINパッドUIの方針と矛盾するため）
- ID: DBで`UNIQUE`制約
- PIN: 平文保存せずbcryptでハッシュ化して保存
- ブルートフォース対策: Upstash Ratelimitでログイン試行回数を制限（IP/ID単位）
- ログイン失敗時、「IDが存在しない」か「PINが違う」かをレスポンスで区別しない（ID列挙対策）
- 入力UIはテキストキーボードではなく数字PINパッド（タッチ操作前提、6歳児でも操作しやすいUI）
